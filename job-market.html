01

The Question

Which skills appear frequently in data roles in Germany, and how should we interpret the salary information attached to those roles? The project uses the public lukebarousse/data_jobs dataset and follows an exploratory notebook workflow.

02

From Nested Lists to Comparable Measures

I converted posting dates to datetime, parsed the stored skill lists with ast.literal_eval, and used explode to create one row per skill mention. Grouping by role and skill then produces counts that can be divided by the number of postings for that role.

df_DE = df[df['job_country'] == 'Germany']
df_skills = df_DE.explode('job_skills')

# Compare skill mentions within each role.
counts = df_skills.groupby(
    ['job_title_short', 'job_skills']
).size()

The notebooks cover skill counts, monthly trends, salary distributions, and demand-versus-salary comparisons. The code excerpt above summarizes the skill-count method.

03

The Denominator Changes the Story

In the saved salary-analysis output, SQL appears in 24 of 48 German Data Analyst postings with salary data, or 50%. Python appears in 18, or 37.5%, and Tableau in 13, or 27.1%. Those percentages describe the salary-reported subset, not every German posting.

A Practical Interpretation

SQL, Python, and BI tools are sensible priorities in this sample. I would not use these 48 postings to estimate the full German salary market or claim that a skill causes higher pay.

04

What Makes the Result Useful

The useful output is a repeatable way to compare roles and skills. Before using it for a current hiring or training decision, I would refresh the source data, show sample counts beside each salary statistic, and consistently filter Germany using job_country. The existing monthly-trend notebook uses job_location, which creates a narrower population.

The monthly charts refer to 2023. This is a historical learning project using Luke Barousse’s public dataset and a course-style notebook structure, rather than a live job-market feed.
